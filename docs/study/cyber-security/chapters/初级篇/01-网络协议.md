# 01 · 网络协议——建立包级别的视野

> 你写了 20 年代码，一直在"应用层"看世界。安全工作需要你下潜到**包级别**：每一个连接、每一个字节、每一次握手都看得见。这一章是所有后续内容的地基。

## 🎯 学习目标

1. 不查资料说清 OSI 七层与 TCP/IP 四层的对应关系，以及"每一层攻什么"
2. 用 Wireshark 抓到并逐包标注一次完整 TCP 握手与挥手
3. 说清 TLS 握手流程，知道抓包里哪些字段可见、哪些永远不可见
4. 手动 dig 一个域名，讲清 DNS 递归解析的完整链路

## 📖 核心知识

### 1.1 双模型对照：每层攻什么

| OSI 层 | TCP/IP 层 | 传输单位 | 安全攻击面（预告） |
|---|---|---|---|
| 应用/表示/会话 | 应用层 | 数据 | SQL 注入、XSS、DNS 隧道 |
| 传输 | 传输层 | 段/数据报 | 端口扫描、SYN Flood、会话劫持 |
| 网络 | 网络层 | 包 | IP 欺骗、路由劫持、ICMP 隧道 |
| 数据链路/物理 | 网络接口层 | 帧/比特 | ARP 欺骗、MAC 泛洪、监听 |

> 工程师视角：你平时调 API 在第 7 层；nmap 在 4 层干活；ARP 欺骗在 2 层。**层次决定工具与防御位置**。

### 1.2 TCP 三次握手（逐包版）

```
客户端                     服务端
   │ --- SYN (seq=x) -------> │   第1次：我想建立连接（我能发）
   │ <-- SYN+ACK (seq=y,ack=x+1) │ 第2次：收到（你能发我能收）
   │ --- ACK (ack=y+1) ------> │   第3次：收到（双向确认完成）
```

- 为什么是三次不是两次：防止历史（迟到）的 SYN 建立无效连接——第二次握手本质是"序列号协商"
- **Wireshark 过滤器**：`tcp.flags.syn==1 && tcp.flags.ack==0`（只看握手的第一个包）；`tcp.stream eq 0`（追踪某条流）

### 1.3 四次挥手与 TIME_WAIT

```
主动方 --- FIN ---> 被动方    （我不发了）
被动方 --- ACK ---> 主动方    （知道了，但我可能还有话说）
被动方 --- FIN ---> 主动方    （我说完了）
主动方 --- ACK ---> 被动方    （再见）→ 主动方进入 TIME_WAIT(2MSL)
```

安全视角：SYN Flood 攻击就是"只做第一次握手"耗尽服务端半连接队列；TIME_WAIT 过多说明本机主动关闭了大量短连接（扫描器的副作用）。

### 1.4 HTTP 细节速查

**方法**：GET / POST / PUT / DELETE / HEAD / OPTIONS / PATCH——OPTIONS 常被用来探测服务器允许的方法（安全测试第一步之一）。

**关键请求头**（安全视角）：

| 头 | 作用 | 攻防意义 |
|---|---|---|
| Host | 虚拟主机路由 | 同 IP 多站的"门牌号" |
| Cookie | 会话凭证 | 窃取目标（XSS 的危害载体） |
| Referer | 来源页 | CSRF 防御的弱手段之一 |
| User-Agent | 客户端标识 | WAF 指纹/爬虫识别 |
| X-Forwarded-For | 代理链 IP | **可伪造**，服务端常误信 |

**状态码**：200/301/302/304/403/404/500 常规；安全测试特别关注 302（登录跳转暗示）、403（有资源但被拦——改路径可能绕过）、500（报错泄露栈信息）。

### 1.5 HTTPS/TLS 握手：抓包能看到什么

```
① ClientHello        → 支持的 TLS 版本/加密套件/随机数/SNI（明文可见！）
② ServerHello+证书   → 证书链（明文可见：域名、颁发者、有效期）
③ 密钥交换           → ECDHE 参数（明文可见参数，看不见密钥本身）
④ ChangeCipherSpec   → 之后所有应用数据都是密文
```

**核心结论**：TLS 保护的是**应用数据**，但 SNI（你要访问哪个域名）、目标 IP、流量大小与时序**全部明文可见**——这就是"流量分析"永远有效的底层原因，也是后面 DNS 隧道/C2 流量检测的物理基础。

动手看：Wireshark 过滤器 `tls.handshake.type == 1`（ClientHello），看 SNI 字段。

### 1.6 DNS 解析全链路

```bash
dig +trace www.example.com   # 从根服务器开始，完整展示递归链
dig www.example.com +short   # 日常用法
```

链路：本机缓存 → 本地 DNS（运营商）→ 根 → .com TLD → 权威服务器。安全关联：子域名枚举（第 1 年 W16 的原理）、DNS 劫持、DNS 隧道（高级篇 C2 流量）。

### 1.7 代理 / VPN / NAT：流量如何被改写

| 技术 | 工作层 | 改写内容 | 安全场景 |
|---|---|---|---|
| HTTP 代理 | 7 | 整个请求可见可改 | Burp 的工作模式 |
| SOCKS 代理 | 5 | TCP 连接中转 | 扫描器流量出口 |
| VPN | 3 | 整个 IP 包封装 | 流量全托管 |
| NAT | 3 | 源 IP:端口重写 | 内网共享出口——日志里只见 NAT IP |

Burp 的工作本质：把浏览器流量指向 127.0.0.1:8080，代理程序"中间人"式读写请求（对 HTTPS 需要安装 Burp 证书，原理就是 TLS 中间人——你有了自己的 CA）。

## 🔬 动手实操（本地授权环境）

```bash
# 1. 抓一次完整握手（终端1）
sudo tcpdump -i any -n "host example.com and port 443"
# 2. 触发流量（终端2）
curl -v https://example.com
# 3. Wireshark 过滤练习
#    tcp.flags.syn==1 && tcp.flags.ack==0     → 所有握手第一包
#    tls.handshake.type == 1                  → 所有 ClientHello
#    dns.qry.name contains "example"          → DNS 查询
# 4. DNS 递归链
dig +trace baidu.com | head -30
```

## ⚠️ 常见坑

1. **只背模型不抓包**——协议知识必须落在"看见的字节"上才长在身上
2. 把 HTTPS 当"绝对安全"——SNI/时序/大小全裸奔
3. 混淆"加密"与"认证"——TLS 两者都做，缺一不可
4. 忽略 DNS：90% 的攻击链第一步是"找到目标"，而找目标靠 DNS
5. 在生产环境随意抓包——先确认权限，抓包内容含敏感数据

## ✅ 自测题

<details>
<summary>1. 为什么 TCP 需要三次握手，两次为什么不行？</summary>

第二次握手同时承载"服务端的 SYN+对客户端的确认"。若只有两次，服务端无法确认自己的初始序列号被正确接收，历史迟到 SYN 会建立无效连接并占用资源。

</details>

<details>
<summary>2. TLS 握手后，Wireshark 还能看到哪些信息？</summary>

SNI（ClientHello 中）、源/目的 IP 与端口、TLS 版本与套件、包大小与时间间隔——即元数据。应用内容不可见。

</details>

<details>
<summary>3. X-Forwarded-For 能作为风控依据吗？</summary>

不能单独作为依据。它是客户端可伪造的头，只有在"每个代理都可信且追加"的前提下，最后一跳才可靠。应结合 TCP 对端 IP。

</details>

<details>
<summary>4. SYN Flood 利用了协议的哪个设计？</summary>

半连接队列：服务端收到 SYN 后分配资源并等待第三次 ACK，攻击者只发 SYN 不回 ACK，耗尽队列。

</details>

<details>
<summary>5. dig +trace 与 dig +short 的区别？</summary>

+trace 从根服务器逐级展示完整解析链（学习/排障用）；+short 只给最终结果（日常用）。

</details>
