# 05 · 操作系统与内网概念——为第 2 年打地基

> 内网渗透听起来吓人，地基其实是两块：**Windows 域的协作模型**和**Linux 的权限边界**。本章只建立"地图"，攻击手法全部留在第 2 年（且仅在授权环境）。

## 🎯 学习目标

1. 画出公司"域环境"的典型拓扑，说清每类角色的职责
2. 用流程图讲一遍 Kerberos 认证（概念级，不涉及攻击）
3. 掌握 Linux 提权排查清单的 5 个位置（本地虚拟机复现）
4. 说清密码存储的演进与"为什么加盐"

## 📖 核心知识

### 5.1 Windows 域：企业为什么用它

```
                ┌──────────────┐
                │  域控制器 DC  │  ← AD 数据库(NTDS.dit)、Kerberos 发证机构
                └──────┬───────┘
        ┌──────────────┼──────────────┐
   ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
   │ 文件服务器│    │ OA/业务机│    │ 员工 PC  │   ← 全部加入域，统一身份
   └─────────┘    └─────────┘    └─────────┘
```

- 一处建账号，全网通用——管理便利（IT 的理由）
- **一次凭据全网有效**——攻击者的黄金乡（安全的代价）
- 组策略（GPO）：下发配置/脚本/策略的机制
- 概念词表：DC（域控）、AD（活动目录）、Domain Admin（域管，"上帝账号"）、Workstation/Server

### 5.2 Kerberos 认证（概念流程）

```
用户 ──① AS-REQ(用自己的密码哈希加密的时间戳)──> KDC/AS
     <──② AS-REP(TGT票据)─────────────────────  验明正身，发票
用户 ──③ TGS-REQ(TGT + 要访问的服务)─────────> KDC/TGS
     <──④ TGS-REP(服务票据 ST)────────────────  发服务票
用户 ──⑤ ST──> 目标服务器  验票放行
```

三个角色：**KDC**（发证的，在 DC 上）、**TGT**（身份凭证缓存）、**ST**（单服务门票）。第 2 年的"域攻击面"几乎全部围绕"票据在哪些环节可以被骗取/伪造"——先把正常流程刻进脑子。

### 5.3 Linux 提权排查清单（本地虚拟机复现）

| 位置 | 命令 | 想找什么 |
|---|---|---|
| SUID 文件 | `find / -perm -4000 -type f 2>/dev/null` | 非默认路径的 SUID（如 /tmp 下的） |
| sudo 权限 | `sudo -l` | (ALL) NOPASSWD 或可绕过的程序 |
| cron 任务 | `crontab -l; ls /etc/cron*` | root 跑的、可写路径的脚本 |
| 可写服务 | `find /etc -writable -ls 2>/dev/null` | systemd 单元指向可写脚本 |
| Capabilities | `getcap -r / 2>/dev/null` | cap_setuid 等 |

**最小复现实验（自建环境）**：
```bash
# 制造一个"可被提权"的 SUID（教学用，实验后删除）
cp /bin/find /tmp/find_demo && sudo chmod u+s /tmp/find_demo
# find 的 -exec 会以文件属主身份执行命令——SUID + find = 经典路径
/tmp/find_demo . -exec whoami \;   # 观察输出：root（实验环境）
sudo rm /tmp/find_demo
```

理解要点：SUID 提权的本质 = "特权程序能否被我诱导执行我指定的动作"。

### 5.4 密码的存储与破解（概念）

| 方案 | 说明 | 被拖库后 |
|---|---|---|
| 明文 | 原始存储 | 全灭（不该存在于 2026 年） |
| 纯 MD5/SHA1 | 快哈希 | GPU 每秒百亿次，秒破弱口令 |
| MD5+盐 | 加随机串 | 拖慢彩虹表，挡不住 GPU 暴破 |
| bcrypt/scrypt/Argon2 | 慢哈希+可调成本 | 每次尝试毫秒级，暴破成本指数上升 |

hashcat 的角色：`-m 0` MD5、`-m 3200` bcrypt……模式编号即算法字典。**破解概念=用算力换可能性**，而防御答案是"让每次尝试足够慢"。

## ⚠️ 常见坑

1. 跳过"正常流程"直接背攻击手法——地基不牢第 2 年全返工
2. 把 Kerberos 当黑盒——它是域攻防的全部语法
3. 在公司电脑上练提权排查——**只在自己虚拟机里做**
4. 轻视"慢哈希"——这是全行业口令安全的胜负手
5. 混淆"认证"（你是谁）与"授权"（你能干什么）

## ✅ 自测题

<details>
<summary>1. 域环境给 IT 和攻击者各带来什么？</summary>

IT：单点身份+统一策略，管理成本骤降。攻击者：一次凭据泄露=全网横行的可能，域管账号成为最高价值目标。

</details>

<details>
<summary>2. TGT 和 ST 的区别？</summary>

TGT 是向 KDC 证明身份的"身份证"（缓存于本机，用于申请各服务票据）；ST 是访问单一服务的"门票"，由目标服务用其机器账户密钥验证。

</details>

<details>
<summary>3. find -perm -4000 在提权排查里的逻辑？</summary>

SUID 程序以属主权限运行；若属主是 root 且程序支持执行外部命令（如 find -exec、vim :!、nmap interactive），普通用户即可借道执行 root 指令。

</details>

<details>
<summary>4. 为什么 bcrypt 比 MD5 适合存密码？</summary>

bcrypt 内置盐+可调慢因子（cost），使单次哈希刻意耗时（~100ms 量级），GPU 暴破成本指数抬升；MD5 的设计目标是快。

</details>

<details>
<summary>5. "认证"与"授权"各举一例？</summary>

认证：Kerberos 验明"你是张三"。授权：ACL/GPO 判定"张三能否读财务盘"。常见漏洞是把认证当授权（如前端隐藏按钮但后端不校验）。

</details>
