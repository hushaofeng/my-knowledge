# 03 · 蓝队体系方向——检测工程与主动狩猎

> 中级篇你学了"接告警"（被动）；这个方向学"造检测"与"主动找"（主动）——检测工程（Detection Engineering）是当前蓝队人才缺口最大的赛道。

## 🎯 学习目标

1. 描述检测工程生命周期
2. 独立编写 3 条递进复杂度的 Sigma 规则
3. 用覆盖度评估法盘点自家检测盲区
4. 跑通一次假设驱动的 Threat Hunting

## 📖 核心知识

### 3.1 检测工程生命周期

```
数据源盘点 → 检测需求(ATT&CK 优先级) → 规则开发 → 测试(红蓝对抗/原子测试)
   → 部署 → 调优(误报治理) → 覆盖度度量 → 循环
```

关键转变：检测是**产品**——有需求、有版本、有测试、有度量，不是"有人报警了才写规则"。

### 3.2 Sigma 规则进阶（三条递进）

```yaml
# ① 原子事件：新服务安装
title: 可疑服务安装
detection:
    sel:
        EventID: 7045
    filter:
        ServiceName|startswith: 'PSEXESVC'   # 已知运维工具
    condition: sel and not filter
level: medium

# ② 行为组合：进程树
title: Office 进程派生命令解释器
detection:
    sel:
        parent_image|endswith: ['\winword.exe', '\excel.exe']
        image|endswith: ['\cmd.exe', '\powershell.exe']
    condition: sel
level: high

# ③ 聚合：短时间暴破后成功
title: 暴破后登录成功
detection:
    fail:
        EventID: 4625
        count: 10
        timeframe: 5m
    success:
        EventID: 4624
    condition: fail | near success
level: critical
```

三级跃迁：**单事件 → 上下文组合 → 时序聚合**——检测能力的本质跃迁。

### 3.3 覆盖度评估（数据源 × 技术）

```
行: ATT&CK 战术/技术（挑与你业务相关的 30 条）
列: 可用日志源（Sysmon/EDR/DNS/Proxy/云审计）
格: ✅有日志有规则 / ⚠️有日志无规则 / ❌无日志
→ ⚠️ 优先补规则，❌ 评估采集成本 → 输出"检测路线图"
```

这张表就是你向管理层要资源的"作战地图"。

### 3.4 蜜罐与欺骗防御

- 低交互：模拟服务端口/横幅（成本低，抓扫描器）
- 高交互：真实系统做诱饵（T-Pot 全家桶：Cowrie/Dionaea 等）
- 蓝队价值：**低噪音高质量告警源**——连蜜罐的没有正常流量；同时测绘对手 TTP
- 部署要点：隔离网段、不接真实业务数据、法律合规（横幅声明）

### 3.5 Threat Hunting（假设驱动）

三种猎杀假设起手：
1. **基于情报**："APT-XX 用 rundll32 加载远端脚本"→ 翻 90 天日志找该模式
2. **基于异常**："内网主机为什么会连这个从未见过的域？"→ DNS 日志基线偏离
3. **基于假设**："如果我是攻击者已落地，我会用什么持久化？"→ 逐持久化位置全量盘点

产出：每猎必有结论（找到=转应急；没找到=确认覆盖+新基线），**狩猎记录即检测规则的种子**。

## 🔬 动手实操

T-Pot 蜜罐部署（家用宽带/云 VPS 均可）→ 7 天后分析抓到的攻击源与 payload → 把 TOP 攻击写成 2 条 Sigma 规则 → 在自己的 Wazuh（中级篇 08 部署的）里适配。

## ⚠️ 常见坑

1. 规则越多越好——噪音淹死的检测工程比没规则更糟
2. 覆盖度表拍脑袋——必须由真实日志字段盘点支撑
3. 蜜罐接了真实业务——引狼入室
4. 狩猎没有产出记录——重复劳动+规则没有来源
5. 只盯 Windows——Linux 云主机是当前主流战场

## ✅ 自测题

<details>
<summary>1. 检测为什么是"产品"而不是"规则集合"？</summary>

它有生命周期管理：需求来源于风险优先级、上线前测试、上线后调优、有覆盖度 KPI——缺乏产品思维的组织检测资产会快速腐烂。

</details>

<details>
<summary>2. "行为组合"类 Sigma 的检测力来自什么？</summary>

单点动作的正常概率高（各自都常见），但来源进程+目标进程的组合正常概率骤降——用上下文把误报率压下去。

</details>

<details>
<summary>3. 覆盖度表里 ❌ 的正确处理？</summary>

先评估"该攻击路径对自身业务的真实风险"，再评估采集成本（license/性能/隐私）——不是全补，是按风险排序补。

</details>

<details>
<summary>4. 蜜罐告警为什么"低噪音高质量"？</summary>

设计上不存在合法用途：任何交互默认恶意（除非误接）——信噪比天然高，适合做"真触发"哨兵。

</details>

<details>
<summary>5. Hunting 与监控的分工？</summary>

监控回答"已知模式有没有出现"（规则驱动、持续）；Hunting 回答"未知威胁是否已存在"（假设驱动、周期性）——狩猎成果沉淀为新的监控规则，形成闭环。

</details>
