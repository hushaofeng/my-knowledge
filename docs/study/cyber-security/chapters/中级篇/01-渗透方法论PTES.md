# 01 · 渗透方法论 PTES——从"打点"到"交付报告"

> 初级阶段你是"知识点"作战；PTES 给你**工程化流程**。它本质是一份交付质量标准：客户买的不是"你黑进去了"，而是"系统性检查 + 可复现证据 + 可执行修复"。

## 🎯 学习目标

1. 说清七阶段各自的输入/动作/产出
2. 用决策树从 nmap 结果选择攻击面
3. 独立完成一台 VulnHub 靶机的完整报告
4. 建立自己的渗透作业模板库

## 📖 核心知识

### 1.1 七阶段总览（输入→动作→产出）

| 阶段 | 输入 | 核心动作 | 产出 |
|---|---|---|---|
| 1 前期交互 | 客户需求 | 范围/授权/规则谈判 | **授权书+测试范围单** |
| 2 情报收集 | 范围单 | 域名/资产/人员/泄露信息 | 资产清单 |
| 3 威胁建模 | 资产清单 | 业务画像、高价值目标排序 | 攻击面优先级 |
| 4 漏洞分析 | 存活服务 | 扫描+手工验证+版本比对 | 漏洞列表 |
| 5 利用 | 验证过的漏洞 | 受控利用、拿权限 | 初始立足点 |
| 6 后渗透 | 立足点 | 提权/横向/取证/维持（范围内） | 影响面证据 |
| 7 报告 | 全程记录 | 分级/复现/修复建议 | **最终交付物** |

> 红线提示：第 1 阶段的**授权书**是一切的合法性来源；无授权的"渗透"在刑法 285 条面前只是犯罪。

### 1.2 扫描结果 → 攻击面决策树

```
nmap -sS -sV 结果
├─ 22 ssh    → 版本漏洞? 弱口令(仅授权字典)? 密钥泄露?
├─ 80/443    → 指纹识别 → 目录爆破 → Web 漏洞族(初级篇 03 的反射)
├─ 445 smb   → 空会话? 共享枚举? 历史协议漏洞(版本比对)
├─ 3306/6379 → 弱口令? 未授权访问? (数据库暴露=直接进场)
└─ 其他端口  → 查 exploitdb/搜索引擎："中间件名+版本号 exploit"
```

决策核心：**版本号 = CVE 的钥匙**。`nginx 1.14 / OpenSSH 7.2` 这类信息直接决定攻击面清单——这就是为什么 `-sV` 永远要开。

### 1.3 靶机报告模板（VulnHub 实战用）

```markdown
# 靶机渗透报告：Kioptrix Level 2
## 1. 目标与环境
## 2. 信息收集
   nmap 结果 + 服务/版本表
## 3. 漏洞分析
   每个候选漏洞：为什么怀疑/如何验证/验证结果
## 4. 利用过程（可复现）
   步骤化命令，每步附"为什么"
## 5. 后渗透
   拿到的权限/能看到的资产/敏感信息
## 6. 修复建议（按漏洞逐条）
## 7. 时间线与工具清单
```

### 1.4 工程师加成

- 用 Git 管理"每次作业"：目录结构（recon/exploit/loot/report）+ 提交记录 = 完整证据链
- 把重复动作脚本化：信息收集流水线（第 1 年 W54 的 subfinder+httpx 就是起点）
- 报告用 Markdown 写 → pandoc 转 PDF，格式专业度碾压同行

## 🔬 动手实操

对 Kioptrix Level 2 严格走七阶段，**卡壳超过 30 分钟才允许看提示**，且提示只看"下一步该看什么"而不是答案。

## ⚠️ 常见坑

1. 拿到 shell 就兴奋收工——后渗透的影响面与报告才是价值
2. 扫描一轮没思路就换靶机——枚举深度不足是新手通病（枚举 3 遍再放弃）
3. 不写过程记录——复盘时证据链断裂，报告写不出
4. 无授权打公网靶机之外的目标——红线
5. 报告写成流水账——按"风险分级+业务影响"组织，客户语言

## ✅ 自测题

<details><summary>1. 为什么"授权书"是阶段 1 而不是形式？</summary>
它定义了合法边界：目标 IP 段、允许的强度、时间窗、应急联系人。超出即违法；它同时保护测试方与被测方。
</details>

<details><summary>2. nmap 发现 6379 开放（Redis），下一步优先验证什么？</summary>
未授权访问：redis-cli 直连测试 CONFIG/INFO 权限——Redis 未授权是历史高频"直接进场"漏洞。
</details>

<details><summary>3. 报告里"影响面"为什么比"payload"重要？</summary>
客户决策依据是业务风险（哪些数据/系统受影响、被利用后果），payload 只是证据。
</details>

<details><summary>4. 枚举为什么值得做三遍？</summary>
不同工具覆盖不同面（端口/目录/用户/接口），且首轮认知会过滤掉"当时没意识到重要"的信息。
</details>

<details><summary>5. 版本号信息如何转化为攻击面？</summary>
"软件名+版本"检索已知 CVE/公开 exploit；同时评估利用条件（需认证?需要特定配置?）是否满足。
</details>
