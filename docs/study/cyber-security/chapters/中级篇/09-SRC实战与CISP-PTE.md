# 09 · SRC 实战与 CISP-PTE——合法战场与硬证书

> SRC（安全应急响应中心）是你唯一能对**真实系统**合法动手的地方；CISP-PTE 是国内攻防岗简历上的硬通货。这一章讲清楚"怎么打才合法、怎么考才高效"。

## 🎯 学习目标

1. 说清 SRC 平台的授权边界与行为红线
2. 建立可持续的挖洞工作流
3. 写出"一次通过"的漏洞报告
4. 完成 CISP-PTE 考纲与备考计划

## 📖 核心知识

### 9.1 SRC 生态与授权边界

| 平台 | 特点 | 新手友好度 |
|---|---|---|
| 补天 | 漏洞量大、企业多 | ⭐⭐⭐⭐ |
| 漏洞盒子 | 同上 | ⭐⭐⭐⭐ |
| 厂商 SRC（字节/阿里/腾讯等） | 范围清晰、规则严、奖励高 | ⭐⭐（要求高） |

**授权边界铁律**：
- 只测平台公告范围（SRC 的 scope 页面），范围外一行代码都不碰
- 遵守速率限制——把业务打挂=违法（285/286 条不豁免）
- 拿到数据即止：**不下载、不翻页、不截图敏感内容**（证明漏洞的最小证据即可）
- 发现高危不扩大战果：验证到"能进"就停，立刻报告

### 9.2 挖洞工作流（可持续版）

```
1. 资产测绘（目标主域）: 子域名枚举(你的工具) → 存活探测 → 指纹识别
2. 边缘资产优先: 老系统/测试环境/被遗忘的子域——补丁滞后区
3. 漏洞匹配: 指纹 → 历史漏洞清单(挂 UI 查) + 逻辑漏洞测试(中级篇 02 的 checklist)
4. 验证与取证: 最小化 PoC（一条请求+一个截图）
5. 提交 → 按平台模板；被拒=学习机会（看官方拒因：无法复现/范围外/低危）
```

节奏建议：**月更节奏**——每月一个完整周末做资产测绘+批量测试，比每天摸 20 分钟高效（碎片时间用来读漏洞报告）。

### 9.3 报告公式（低危→高分的秘密）

```
标题：[厂商][系统][漏洞类型]一句话（例：XX 学院招生系统存在未授权访问可查询全部考生信息）
危害定级：说"业务影响"不说"技术名词"（可查 3 万考生身份证号 > "未授权接口"）
复现步骤：1-2-3 步，每步一条请求/一个截图，可直接照抄复现
影响面：波及多少用户/什么数据/能进一步到哪
修复建议：具体到代码层（加鉴权注解/收紧 CORS/下线接口）
```

被拒 Top3 原因：复现不了（步骤缺失）、范围外（测了不该测的）、重复提交——**报告质量决定通过率**。

### 9.4 CISP-PTE 备考

考纲四模块与权重：Web 渗透（注入/XSS/文件上传/命令执行）、中间件（Tomcat/Weblogic/JBoss 历史洞）、操作系统（Windows/Linux 提权）、内网（MSF 基础）。

| 阶段 | 时间 | 动作 |
|---|---|---|
| 对照缺口 | 2 周 | 考纲逐项自评，标记弱项 |
| 专项攻坚 | 4 周 | 弱模块各配 2-3 个靶场实战 |
| 全真模拟 | 2 周 | 限时完整流程演练（发题→报告） |
| 手速与细节 | 1 周 | 截图习惯/报告模板背熟 |

实战考试要点：**过程截图即证据**——考官按"攻击链完整性+报告质量"评分，不是只看 flag。

## 🔬 动手实操

注册补天 → 只看"公开教育行业公益测试范围"资产 → 用你的子域名工具跑第一个目标 → 全程遵守 9.1 铁律 → 第一份报告（哪怕低危）。

## ⚠️ 常见坑

1. Scope 之外"顺手"测同 IP 其他站点——超范围即违法
2. 高危洞"多翻几页证明危害"——翻页=侵犯公民个人信息，红线
3. 报告只贴 payload 不写步骤——复现不了=拒单
4. 备考只刷题不做靶机——PTE 是实操考
5. 收集"证明材料"过度——最小证据原则，保护自己也保护他人

## ✅ 自测题

<details>
<summary>1. SRC 测试为什么"拿到数据即止"？</summary>

法律上"获取数据"的量与类型决定是否触刑（侵犯公民个人信息罪）；渗透的目的是证明漏洞存在，不是展示破坏力——最小证据原则既合规也是职业素养。

</details>

<details>
<summary>2. 为什么"边缘资产"优先测？</summary>

测试环境/老系统补丁与监控通常滞后于主站，攻击者实际也这么想——投入产出比最高，且多为低危起步的好战场。

</details>

<details>
<summary>3. 报告标题的三个要素？</summary>

厂商+系统+漏洞类型与一句话影响——让审核员 3 秒判断价值与归属。

</details>

<details>
<summary>4. PTE 实操考的评分重心？</summary>

攻击链完整性与报告质量：过程截图、每步依据、修复建议——只拿 flag 不写过程得不了高分。

</details>

<details>
<summary>5. 被拒后正确的动作？</summary>

读拒因→区分"质量差/范围外/重复"→属质量问题按公式改写重交，属范围问题立即停止该目标——把拒单当免费评审。

</details>
