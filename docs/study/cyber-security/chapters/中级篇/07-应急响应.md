# 07 · 应急响应——被打了之后的两小时

> 应急响应是蓝队的"急诊科"：目标是在最小损失下**止血、定位、复原、复盘**。护网期间 70% 的初级岗工作就在这里——这也是你的第一张"攻防任务入场券"。

## 🎯 学习目标

1. 背下应急六步法及每步的关键动作
2. Linux/Windows 排查清单能默写（进程/网络/持久化）
3. 会从 access.log 回溯"落马时间线"
4. 产出标准应急报告

## 📖 核心知识

### 7.1 六步法（PICERL）

| 步 | 动作 | 关键问题 |
|---|---|---|
| 1 准备 | 预案/联系人/工具包 | 事发前做过什么 |
| 2 识别（Identification） | 告警确认/影响面初判 | 是真事件吗？影响多大 |
| 3 遏制（Containment） | 断网/隔离/封 IP | **先止血**，别急着删 |
| 4 根除（Eradication） | 找持久化/清后门/改密 | 不除根，三天后复发 |
| 5 恢复 | 干净版本回切/加固 | 从可信源恢复 |
| 6 复盘（Lessons） | 时间线/根因/改进项 | 谁在什么时候用什么进来 |

**顺序红线**：先取证再清除——"手起刀落删马"是最常见的业余错误（证据没了，溯源断了）。

### 7.2 Linux 排查清单（背熟）

```bash
# 进程：谁在吃 CPU？路径对吗？
top -c; ps aux --sort=-%mem | head
ls -l /proc/<pid>/exe          # 真实路径（deleted 标记=已删仍在跑，恶意样本特征）

# 网络：谁在监听？连着谁？
ss -tlnp                       # 异常监听端口
ss -tnp state established      # 外连 IP——反查威胁情报

# 持久化五大位
crontab -l; ls -la /etc/cron*            # 1 定时
cat /etc/rc.local; systemctl list-unit-files --state=enabled   # 2 自启
ls ~/.ssh/authorized_keys /root/.ssh/authorized_keys           # 3 密钥后门
cat /etc/passwd | grep -E ':0:'          # 4 UID=0 的额外账号
ls -la /etc/ld.so.preload /etc/ld.so.conf.d/   # 5 动态链接劫持(rootkit 常用)

# 历史/痕迹
history; last -F; lastlog
stat /var/log/wtmp    # 日志被删的痕迹：文件大小骤减/时间戳异常
```

工具位：chkrootkit/rkhunter（rootkit 扫描）、BusyBox 静态版（系统被篡后用干净二进制查）。

### 7.3 Windows 排查清单

| 位置 | 命令/路径 | 找什么 |
|---|---|---|
| 进程 | Task Manager / `wmic process get name,executablepath,processid` | 无签名/临时目录路径 |
| 网络 | `netstat -ano` + PID 映射 | 异常外连 |
| 服务 | `sc query` / 事件 **7045**（新服务安装） | 随机名服务 |
| 计划任务 | `schtasks /query /fo LIST /v` | 可疑周期任务 |
| 注册表持久化 | Run/RunOnce/Winlogon/服务 ImagePath | 恶意启动项 |
| 账户 | 事件 **4720**（建号）、隐藏 `$` 账号 | 新增可疑账号 |
| 登录 | **4624**（成功）/4625（失败）/4648（显式凭据） | 暴破→成功的时间序列 |

### 7.4 Webshell 溯源时间线（access.log 回溯法）

```
1. 找落马点：grep 危险特征（eval/base64_decode/system）→ 定位被利用的漏洞文件
2. 找首次写入：webshell 文件的 ctime 之前，找该路径的上传/写入请求
3. 还原攻击序列：
   20:01 POST /upload.php  200   ← 传马
   20:01 GET  /img/x.php   200   ← 落地验证
   20:05 POST /img/x.php   200   ← 持续控制
4. 圈定影响面：该 IP 全部请求 / 会话内其他被访问路径（可能有第二个马）
5. 对应修复：漏洞修复+马清理+密钥全换
```

查杀工具：D 盾/河马（Windows 扫描目录）、`find . -name "*.php" | xargs grep -l "eval("` 粗筛。

### 7.5 应急报告模板

```markdown
1. 事件概述（一句话：什么系统、什么时间、什么问题、什么影响）
2. 时间线（UTC 时间轴：发现/遏制/根除/恢复）
3. 攻击路径还原（证据：日志片段+文件样本 hash）
4. 影响面（数据/系统/凭据是否泄露）
5. 处置动作清单
6. 根因与改进项（分：紧急/30天/长期）
```

## 🔬 动手实操

自建"被黑靶机"：虚拟机装 WordPress + 故意留弱口令 → 让同好/自己模拟攻击 → 按清单完整走一遍 PICERL，产出报告。Boto 壳/噬蜜类应急靶场亦可。

## ⚠️ 常见坑

1. 上来就删马——先取证（内存/日志/文件副本+hash）
2. 只看当前进程——持久化五位不查，清了也白清
3. 忽略"攻击者也在看你的响应"——隔离前先别打草惊蛇（视场景）
4. Windows 事件日志没开审计——事发后无米下锅，平时就要开
5. 报告不写根因——同一洞一个月后再被打就是耻辱

## ✅ 自测题

<details>
<summary>1. /proc/&lt;pid&gt;/exe 显示 "(deleted)" 说明什么？</summary>

进程运行的可执行文件已被删除——常见于恶意样本自我删除防分析，或正常程序升级；结合路径/签名/外连判断，是重要告警特征。

</details>

<details>
<summary>2. 为什么先遏制再根除？</summary>

遏制（隔离/断网）防止损失扩大且保留现场；直接删除可能触发攻击者的"毁尸"逻辑，且没有证据链无法溯源与定责。

</details>

<details>
<summary>3. Windows 上"新增隐藏管理员账号"查哪两个点？</summary>

事件 4720（用户创建）核对时间窗；`net user` 带尾符 `$` 账号 + 注册表 SAM 导出核对（隐藏账号不显示于常规列表）。

</details>

<details>
<summary>4. access.log 溯源时"ctime 之前的写入请求"意味着什么？</summary>

webshell 文件的创建时间之前存在的写入类请求（上传/编辑器/模板修改）就是落马通道——找到它才能定位漏洞根因。

</details>

<details>
<summary>5. 应急报告的"根因"与"改进项"为什么分开写？</summary>

根因回答"为什么能进来"（技术事实），改进项回答"以后怎么办"（分时限行动项）——混写会让管理者只记住情绪记不住行动。

</details>
