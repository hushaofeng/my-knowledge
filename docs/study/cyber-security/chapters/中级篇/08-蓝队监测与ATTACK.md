# 08 · 蓝队监测与 ATT&CK——告警背后的人

> SIEM 每天推给你 3000 条告警；初级岗的价值=把真威胁从噪音里捞出来。这一章教你**研判方法论**与**检测工程入门**——护网蓝队岗的核心技能树。

## 🎯 学习目标

1. 画出 SIEM 数据流水线
2. 在 Wazuh 写出第一条自定义规则
3. 用"三问法"完成一次告警研判
4. 把已学攻击技术映射到 ATT&CK 矩阵

## 📖 核心知识

### 8.1 SIEM 流水线

```
日志源 ──采集──> 归一化(字段标准化) ──> 规则/UEBA ──> 告警 ──> [人] 研判 ──> 处置
(Web/OS/EDR/网络设备)      Agent/Syslog          关联/聚合/基线            工单/封禁/应急
```

蓝队的本质：**日志质量决定检测上限**。垃圾进垃圾出——所以"平常有没有开审计"是蓝队最先盘点的事。

### 8.2 Wazuh 自定义规则入门

```xml
<!-- /var/ossec/etc/rules/local_rules.xml -->
<group name="local,webshell,">
  <rule id="100100" level="10">
    <if_sid>31108</if_sid>              <!-- Web 请求类父规则 -->
    <regex>POST /upload/.+\.php</regex> <!-- 上传目录被 POST 执行 -->
    <description>疑似 webshell 执行：上传目录 POST 请求</description>
  </rule>
</group>
```

要素：id（100000+ 自定义段）/ level（告警级别）/ if_sid（继承父规则）/ regex|match（特征）。写规则的思维：**把"攻击的日志特征"翻译成"字段的正则+阈值+关联"**。

### 8.3 告警研判三问法

```
一问真实性：日志可信吗？（IP 可伪造吗？时间线连续吗？代理日志 vs 主机日志对得上吗？）
二问严重性：影响什么资产/数据？漏洞可利用性？横向可能？
三问下一步：立即处置（封IP/隔离）还是升级（应急）？要哪些补充信息？
```

**误报治理**：每类告警建"误报白名单"（如扫描器自身 IP、变更窗口）——但白名单要写明"为什么+有效期"，防止成为黑洞。

### 8.4 流量侧检测概念

| 特征 | 检测点 |
|---|---|
| Webshell 流量 | POST 到上传目录、请求响应长度分布异常、UA 与行为不匹配 |
| C2 心跳 | 固定间隔外连（间隔方差小）、低流量长连接、DGA 域名（随机字母长域名） |
| DNS 隧道 | 单域名 TXT 查询量异常、子域名熵值高 |
| 横向扫描 | 内网 ICMP/TCP 扫描模式、SMB 认证风暴 |

### 8.5 ATT&CK 矩阵：攻防的公共语言

结构：14 个战术（列：初始访问→影响）× 每战术下技术（行：如 T1059 命令脚本解释器）。

**映射练习**（用已学中级内容填）：

| 已学技术 | ATT&CK 战术 | 技术编号（示例） |
|---|---|---|
| 钓鱼/边界利用 | 初始访问 | T1566/T1190 |
| webshell | 持久化 | T1505.003 |
| PsExec 横向 | 横向移动 | T1021.002 |
| Kerberoasting | 凭据访问 | T1558.003 |
| 计划任务后门 | 持久化 | T1053 |

价值：有了编号，检测规则、报告、复盘全部对齐同一种语言——这是与国际接轨的"术语操作系统"。

### 8.6 Sigma 入门

```yaml
title: 上传目录 Webshell 执行
logsource:
    category: webserver
detection:
    sel:
        cs-method: 'POST'
        cs-uri-stem|contains: '/upload/'
        c-extension: '.php'
    condition: sel
level: high
```

Sigma = 检测规则的"跨平台普通话"（一份 YAML 转 Splunk/Elastic/Wazuh 规则）——检测工程的可移植资产。

## 🔬 动手实操

Wazuh 单机部署（docker 或 OVA）→ 造 3 个事件（暴破失败/webshell 请求/新用户创建）→ 观察默认告警 → 为其中之一写自定义规则 → 触发验证。

## ⚠️ 常见坑

1. 只学工具不学研判——工具会变，方法论不变
2. 规则一写就"level 15 全网告警"——告警疲劳是检测工程第一杀手
3. 把 ATT&CK 当背书材料——它是映射工具，用起来才有价值
4. 忽略白名单管理——半年后没人知道某条白名单为什么存在
5. 只看告警不看基线——"正常长什么样"都不知道，异常无从谈起

## ✅ 自测题

<details><summary>1. 为什么说"日志质量决定检测上限"？</summary>
规则再好，日志缺字段（如未开命令审计/未记录 DNS）就永远检不出对应行为——数据源覆盖先于规则编写。
</details>

<details><summary>2. 研判"外连 C2 心跳"最关键的证据？</summary>
外连时序规律性（固定间隔/抖动极小）+ 目标域名/IP 情报 + 结合主机侧是否有对应进程——单靠流量特征容易误判定时任务。
</details>

<details><summary>3. ATT&CK 映射对护网蓝队的实际用处？</summary>
统一攻击描述语言：值班报告写"T1059+T1053 组合"各方即时理解；也用于盘点检测覆盖（哪些战术有日志无规则）。
</details>

<details><summary>4. 告警级别怎么定才不疲劳？</summary>
按"置信度×影响"分级：高置信高影响才 high；低置信但可观测的放 low/info 只记录不推送——推送量控制在人能处理的上限内。
</details>

<details><summary>5. Sigma 的核心价值？</summary>
检测逻辑与平台解耦：一次编写，可转换到 Splunk/Elastic/QRadar 等——规则成为可迁移的组织资产。
</details>
