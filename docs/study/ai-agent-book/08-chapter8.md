# 《AI Agent 实战》第八章知识笔记：Agent 的持续进化

---

## 一、核心问题：能力悖论

**核心矛盾**：Agent 可以零样本解决从未见过的复杂任务，却可能在处理一万次相似任务后仍然犯下第一天的错误。

**关键区别**：
- **保存经历 ≠ 从经历中学习**
- 把轨迹放进向量库只是"记得更多"
- 真正的学习需要：评价 → 对照 → 归纳 → 验证

---

## 二、学习信号的获取：三层轨迹验证

### 2.1 三层验证结构（图8-2）

| 层级 | 验证器类型 | 回答的问题 | 可靠性 |
|------|------------|------------|--------|
| 底层 | 结果验证器 | "事情是否真的办成" | 最高（依赖环境真值） |
| 中层 | 过程验证器 | "是否以允许的方式办成" | 高（依赖规则检查） |
| 上层 | 质量验证器 | "是否办得合适" | 需要LLM Rubric |

**原则**：越靠下的指标越应依赖代码和环境真值，只有难以形式化的部分才交给语言模型。

### 2.2 客服 Agent 的七维评价量表（表8-1）

| 维度 | 验证问题 | 主要证据 |
|------|----------|----------|
| 任务结果 | 核心诉求是否解决 | 最终环境状态、工具结果 |
| 规则遵从 | 是否违反政策/权限/流程 | 政策库、动作轨迹 |
| 隐私边界 | 是否泄露不应提供的信息 | 回复文本、数据访问记录 |
| 事实可靠性 | 陈述是否有知识或工具支持 | 引用来源、工具返回 |
| 承诺—行动一致性 | 声称完成的操作是否真实发生 | 回复与工具日志对照 |
| 表达质量 | 是否自然、简洁 | 对话全文、语言Rubric |
| 合规变通 | 原方案不可行时是否找到替代路径 | 用户目标、政策与后续动作 |

**关键维度**："承诺—行动一致性"是Agent场景特有的，需要验证回复与实际工具调用是否一致。

### 2.3 验证器设计原则

1. **验证结果不应压缩成标量**：维度化信号保留问题性质和证据位置
2. **LLM验证器需要校准**：准备专家标注轨迹，检查一致性
3. **验证与诊断分离**：验证器负责评价，独立的诊断模块决定修改位置

## 三、四种更新载体及其适用边界

### 3.1 四种方式对比（表8-2）

| 更新方式 | 适合承载 | 主要优势 | 主要局限 |
|----------|----------|----------|----------|
| **经验知识库** | 事实、经验规律、例外与来源 | 更新快、可追溯、可按需检索 | 依赖检索和模型正确应用 |
| **Prompt与Skill** | 可语言化的判断原则和操作规范 | 可解释、作用范围可控 | 容易膨胀、冲突或被忽略 |
| **程序与Harness** | 确定性流程、工具和强约束 | 可测试、执行稳定、成本低 | 开发与维护成本较高 |
| **模型参数** | 高维感知、生成风格和隐式策略 | 泛化能力强、推理开销低 | 更新与回归成本高 |

**选择依据**：不是经验出现多久，而是目标能力能否被某种载体自然表达。

### 3.2 经验知识库

**知识来源区分**：
- 第三章：从用户对话提取"用户与世界是什么样的"
- 本章：从Agent轨迹提取"在什么条件下应该怎样做"

**三层数据结构**：
1. **不可变原始轨迹** → 用于审计
2. **单次运行分析** → 记录成败与候选教训
3. **多条同类轨迹归纳** → 形成面向未来的知识文档

**知识提炼管道五步**：
1. 保存不可变轨迹和环境结果
2. 为单次运行生成结构化分析
3. 按任务族聚合同类运行，建立证据表
4. 达到支持门槛的候选写入正式文档
5. 在新任务上测试迁移效果

### 3.3 Prompt与Skill学习

**系统提示学习（System Prompt Learning）**：
- 预训练学习知识，微调塑造习惯性行为
- 系统提示学习是"用明确语言提醒未来的自己"
- 与强化学习的区别：编辑文字 vs 梯度下降修改参数

**提示词自动优化路线**：
- DSPy：在开发集上搜索指令和示例
- OPRO：让LLM根据历史得分提出候选
- GEPA：利用失败轨迹反思生成互补候选

**Skill学习原则**：
- 候选Skill应说明：何时加载、前置条件、操作步骤、已知陷阱、验证方法
- 先在Skill库中搜索近似能力，优先做局部patch
- 新能力才创建新目录，避免重复手册

### 3.4 程序与Harness

**浏览器工作流生命周期（六步）**：
1. **捕获轨迹**：记录动作、参数、元素定位证据
2. **参数化**：把字面量识别为模板变量
3. **定义状态检查**：执行前检查、执行后检查、最终状态检查
4. **候选验证**：沙盒重置后完整回放，全部检查通过才发布
5. **匹配与回放**：新任务匹配工作流，提取参数，由Playwright执行
6. **失效与重学**：检查不通过时立即停止，回退到完整Agent探索

**关键验证**：动作执行成功 ≠ 任务成功，必须有最终状态检查。

**可证伪的变更契约**：每次修改需声明失败证据、推断根因、目标组件、预期修复、可能受损行为、验证用例。

### 3.5 参数学习

**适用场景**：
- 医疗影像理解
- 自然语音韵律
- 消除"AI味"
- 长程规划
- 其他难以符号化的高维能力

**训练数据来源**：
- 高质量示范 → SFT
- 明确偏好 → 成对数据
- 可靠环境奖励 → RL

**注意事项**：进入训练前需去除隐私、过滤错误轨迹、保留回归集；训练后检查遗忘和安全对齐。

## 四、优化层级的正交轴

**从产物内容到更新方法**：
1. 单条规则或记忆（最内层）
2. 结构化上下文
3. 工作流
4. Harness代码
5. 产生候选方案的优化器代码（最外层）

**原则**：搜索空间越大，可信根越重要。优先局部补丁，跨组件问题才上升到更高层级。

## 五、持续进化闭环

### 5.1 双循环结构（图8-5）

| 循环 | 职责 | 特点 |
|------|------|------|
| **在线执行循环** | 完成任务、记录证据 | 不直接改写正式Agent |
| **离线进化循环** | 聚合轨迹、诊断根因、生成候选、验证发布 | 通过版本化连接 |

### 5.2 Voyager案例

**三个咬合机制**：
1. **自动课程生成器**：根据当前能力提出适中目标
2. **技能库**：保存成功程序为可检索、可组合代码
3. **迭代提示机制**：环境观察、错误、验证结果带回下一轮

**效果**：3.3倍独特物品，2.3倍探索距离，15.3倍解锁速度。

### 5.3 分层评估指标（表8-3）

| 指标 | 回答的问题 | 主要证据 |
|------|------------|----------|
| 候选修改有效率 | 更新器是否提出有价值修改 | 候选接受率与增益 |
| 产物激活率 | 任务Agent是否正确加载新产物 | 检索、路由与工具调用轨迹 |
| 遵循成功率 | 激活后是否按新规则执行 | 动作序列与过程验证器 |
| 留出任务增益 | 整体是否改善未参与进化任务 | held-out成功率、质量与成本 |

**关键区分**：
- Harness更新能力：产生有价值的持久修改
- Harness受益能力：任务Agent找到、激活并正确使用修改

### 5.4 长期评价五类结果

1. **回退（Regression）**：新经验是否与已有经验冲突
2. **泛化能力**：未覆盖场景的效果提升
3. **Token效率**：完成任务的成本
4. **安全性**：规则、隐私和拒绝边界是否漂移
5. **长期工程质量**：维护复杂度、架构一致性、迁移负担

## 六、安全边界

### 6.1 三道安全边界

| 边界 | 内容 |
|------|------|
| **证据与指令隔离** | 原始网页/工具输出不可直接写入Skill，需经LLM总结，通过PR和reviewer审阅 |
| **候选与正式隔离** | 新产物先进入候选区，通过安全检查和回归测试后才能服务真实流量 |
| **安全机制不可自我修改** | 验证器、测试用例、发布门槛、审计日志不可被业务Agent修改 |

### 6.2 风险类型

- 提示注入被总结为经验
- 恶意软件包被封装为工具
- 有缺陷的验证器持续批准退化候选

## 七、睡眠学习：整合与遗忘

### 7.1 睡眠学习周期五步

1. **触发**：达到时间/数量/容量/错误阈值，无高优先级在线任务
2. **定向**：读取正式知识和版本，了解已有能力和边界
3. **采集与整合**：寻找新信号，合并重复，标记冲突，生成局部补丁
4. **验证与审批**：评估候选，高风险写入等待人工批准
5. **修剪与索引**：更新索引，标记过期能力，保留回滚版本

### 7.2 周期性离线整理内容

- 合并重复经验，保留来源和版本
- 局部规则从全局Prompt移到领域Skill
- Prompt和Skill保持结构清晰，避免"99条军规"
- 重新验证长期未使用的工具
- 删除被新证据推翻的知识
- 从原始基座模型重新训练LoRA

## 八、可验证闭环的边界

### 8.1 自动科研的压力测试

**三类问题**：
1. **实现漂移**：变难后退回训练数据中熟悉的普通实现
2. **认识论过度乐观**：把噪声解释为发现，忽略失败和阴性结果
3. **隐性判断力不足**：不知道什么基线重要、哪个异常值得追踪

### 8.2 改进方向

- **结论与证据分离**：每类声明链接到可审计来源
- **保留负面结果**：失败实验拥有与成功结果相同的可检索地位
- **维护搜索多样性**：保留暂时低分但不同质的分支
- **人类高层介入**：定义问题、审查标准、解释反常、决定停止

## 九、核心公式/原则总结

### 9.1 学习信号获取

```
三层验证 = 结果验证（环境真值）+ 过程验证（规则检查）+ 质量验证（LLM Rubric）
```

### 9.2 更新载体选择

```
能力可符号化 → 知识/Prompt/Skill/程序
能力不可符号化（高维感知、风格） → 参数
```

### 9.3 进化闭环

```
在线执行（记录证据）→ 离线进化（聚合/诊断/生成候选）→ 验证门槛 → 灰度发布
```

### 9.4 安全边界

```
可信根 = 验证器 + 测试用例 + 发布门槛 + 审计日志 + 稳定版本备份
可信根不可被业务Agent修改
```

## 十、思考题要点

### Q1：经验文档的多轨迹支持判断
- 检查API版本差异
- 区分"经验被推翻"vs"适用条件变化"
- 需要版本标记和适用范围声明

### Q2：满意度与违规的护栏设计
- 满意度可能是违规带来的
- 需要多维护栏指标：规则遵从、隐私、合规
- 单一信号不能作为学习目标

### Q3：修改位置选择依据
- 可语言化程度
- 执行确定性要求
- 验证成本
- 回滚难度

### Q4：权限边界划分
- 可修改：Prompt、Skill、知识库、工具
- 不可修改：验证器、测试用例、发布门槛、审计日志

### Q5：知识库增长后的管理
- 版本控制
- 时效标记
- 淘汰机制
- 冲突检测

### Q6：医疗客服协同方案
- 参数：自然语言风格
- 知识：最新医疗指南
- Skill：问诊流程
- 代码：硬性规则约束（用药禁忌、剂量上限）
