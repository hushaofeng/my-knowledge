## 一、核心公式：Agent = LLM + 上下文 + 工具

这是全书的核心框架，三个要素缺一不可：

| 要素 | 含义 |
|------|------|
| **LLM** | 大语言模型，提供核心推理能力 |
| **上下文** | Agent 看到的信息，决定"知道什么" |
| **工具** | Agent 能执行的动作，决定"能做什么" |

三个维度理解：
- **实现层**：技术实现的角度
- **直觉层**：功能感知的角度
- **学术层**：理论研究的角度

## 三、两朵乌云：Agent 发展的两大挑战

### 3.1 第一朵乌云：实时交互

**问题**：当前Agent是"请求-应答"模式，无法边听边想、边说边想

**两条解决路径**：

```
┌─────────────────────────────────────────────────────────────┐
│ 路径一：架构上做快慢分离                                      │
│   • 前台快模型：维持对话节奏                                   │
│   • 后台慢模型：负责深度思考                                   │
├─────────────────────────────────────────────────────────────┤
│ 路径二：把推理本身做快                                        │
│   • 小米MiMo：1T参数模型达1000+ token/s                       │
│   • Taalas HC1：80亿参数模型达17000 token/s，响应<100ms        │
└─────────────────────────────────────────────────────────────┘
```

**核心洞见**：当生成速度足够快，"想完再说"和"边想边说"的体验差距就被抹平了

### 3.2 第二朵乌云：持续学习

**问题**：模型训练后几乎不再成长，经验随着上下文被丢弃

**两种假设对比**：

| 假设 | 观点 | 含义 |
|------|------|------|
| **小世界假设** | 大模型能装下几乎所有通用知识 | 瓶颈在于数据，训练一次即可 |
| **大世界假设** | 用户/公司的具体知识不在训练语料中 | 需要上岗后持续学习 |

**持续学习的方式**：
- 把经验写成知识文档
- 转化为指令或程序
- 经过筛选后更新模型参数

## 四、模型与 Agent 的共同演进

### 4.1 自我强化的飞轮

```
用户提出真实难题
      ↓
应用层用Harness暂时补上模型做不好的事
      ↓
这些补救沉淀成训练信号
      ↓
下一代模型内化这些能力
      ↓
对应的Harness代码可以删掉
      ↓
（循环继续）
```

### 4.2 Harness 的命运

**模型会吃掉 Harness 吗？**

答案：会，一层一层地吃，但永远不会完结

**原因**：
1. 训练以月计，模型等得起，业务等不起
2. 模型无法内化所有业务约束与偏好
3. 每代模型都会打开新的能力前沿

> **《苦涩的教训》在Agent时代的读法**：通用方法终将胜出，但"终将"二字里的每一段路，都是Harness铺出来的

### 4.3 护城河的本质

**对造模型的人**：把飞轮转起来，让真实场景的反馈尽快回流到训练里

**对造应用的人**：
- Harness 是短期最锋利的技术杠杆
- 但要清醒：模型会内化约束，抹平只靠 Harness 的优势
- 真正的长久护城河在技术之外：
  - 独占的数据
  - 稳固的渠道
  - 用户的信任
  - 网络效应
  - 人与Agent协作的复杂场景

## 五、三个不会过时的问题

无论模型如何迭代，这三个问题永不过时：

| 问题 | 对应要素 |
|------|----------|
| 看到什么 | 上下文 |
| 能做什么 | 工具 |
| 如何验证做得对不对 | 评估 |

> 这些问题描述的是一个智能系统与世界交互的基本方式

## 六、关键洞见与金句

1. **Harness的本质**：每一层兜底逻辑都记录着模型此刻还做不稳的地方

2. **飞轮的力量**：真实业务、反馈数据与模型迭代咬合得越紧，别人越难从外部追上

3. **最深的护城河**：同时握住模型和Harness两端，让它们互相喂养、共同进化

4. **应用层的策略**：把Harness用来争取时间，用这段时间构筑技术之外的壁垒

5. **学习的本质**：模型最强的能力，终将不是记住，而是学习与适应

---

## 七、行动建议

1. **亲手实践**：读懂和做出来之间，隔着一条只能靠双手跨过的河

2. **保持清醒**：掌握判断力，而非某个API的具体用法

3. **去创造**：Agent能通过写代码创造新的能力，甚至改进自己
