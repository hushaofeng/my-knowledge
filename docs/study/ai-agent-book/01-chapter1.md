# 《AI Agent 实战》Chapter 1 核心知识点笔记

## 一、Agent 核心公式

### 公式定义
**Agent = LLM + 上下文 + 工具**

### 直观理解
| 组件 | 直觉比喻 | 功能定位 | 学术概念 |
|------|----------|----------|----------|
| **LLM** | 大脑 | 决策核心：理解意图、思考规划、做出判断 | Policy（策略） |
| **上下文** | 眼睛 | 感知信息：环境信息、用户记忆、领域知识、任务进展 | Observation Space（观察空间） |
| **工具** | 手脚 | 行动能力：感知、执行、协作、事件触发、用户沟通 | Action Space（动作空间） |

### 关键洞察
- **观察空间与动作空间 = LLM 与外部环境的接口**
- 没进入观察空间的信息，对模型"不存在"
- 没进入动作空间的操作，模型只能"纸上谈兵"
- **在模型固定时，扩展上下文和工具是最主要的工程杠杆**

---

## 二、工具体系（五大类型）

### 工具分类
| 类型 | 功能 | 典型示例 |
|------|------|----------|
| **感知工具** | 访问信息 | 搜索引擎、文件系统、API、数据库 |
| **执行工具** | 改变世界 | 代码执行、文件操作、系统命令、API调用 |
| **协作工具** | 分工合作 | 委托子Agent、人类确认、多Agent协调 |
| **事件触发工具** | 外部驱动 | 新邮件、定时任务、Webhook回调 |
| **用户沟通工具** | 信息传递 | 文字消息、语音通话、邮件 |

### 工具调用四步流程
```
1. 声明工具（名称、用途、参数）
      ↓
2. 模型自主决策（调不调、调哪个、传什么参数）
      ↓
3. 执行工具，结果追加到上下文
      ↓
4. 模型基于结果决定下一步
```

### 工具设计核心原则
- **通用基础能力用于组合与探索**
- **专用工具用于约束高风险和强业务规则操作**

## 三、上下文结构

### 上下文五层组成
| 组件 | 类型 | 功能 |
|------|------|------|
| **系统提示词** | 静态前缀 | Agent的"岗位说明书"，定义身份、权限、行为准则 |
| **工具定义** | 静态前缀 | 声明可用工具的名称、功能、参数格式 |
| **用户消息** | 动态轨迹 | 用户输入 + RAG检索的外部知识 |
| **模型回复** | 动态轨迹 | reasoning（思考）+ content（回复）+ tool_calls（工具调用） |
| **工具执行结果** | 动态轨迹 | Agent下一步思考的直接依据 |

### 核心公式
**上下文 = 静态前缀（系统提示词 + 工具定义）+ 轨迹（动态消息历史）**

---

## 四、ReAct 循环

### 定义
**ReAct = Reasoning + Acting**

### 三环节循环
```
思考（Reasoning）→ 行动（Acting）→ 观察（Observing）→ 思考 → ...
```

### 轨迹（Trajectory）结构
- 轨迹是Agent执行任务过程中积累的消息历史
- 每次LLM调用都看到**完整轨迹**
- 轨迹具有累积性，保持Agent对任务的全局认知

### 多币种收入汇总示例（3次迭代）
```
第1轮：分析任务 → 并行调用3个货币转换工具
第2轮：基于结果 → 调用代码解释器计算
第3轮：确认完成 → 生成最终答案
```

---

## 五、Agent 学习机制（三层次）

| 层次 | 机制 | 时间尺度 | 特点 |
|------|------|----------|------|
| **上下文适应** | 任务内调整 | 即时 | 快速、低成本，受上下文窗口约束 |
| **外部产物更新** | 跨任务保留 | 持久 | 知识文档、Prompt/Skill、程序与Harness |
| **参数更新** | 模型后训练 | 长期 | 部署成本高，形成广泛泛化能力 |

**三条路径协同工作**：上下文负责临场适应，外部产物负责可控积累，参数负责内化隐式能力。

## 六、Harness 工程

### 扩展公式
**Agent = LLM + [上下文 + 工具 + 约束 + 验证 + 纠正] = Model + Harness**

### Harness 五要素
| 功能 | 职责 | 核心原则 |
|------|------|----------|
| **上下文** | 提供感知信息 | 信息充分性：每个决策点基于足够信息 |
| **工具** | 提供行动手段 | 接口清晰：命名直观、参数有例子、边界有说明 |
| **约束** | 设定行为边界 | 故障安全默认值：默认关闭，显式开放 |
| **验证** | 判断结果对错 | 输入隔离：检查结构化数据，不信任自由文本 |
| **纠正** | 自动修正恢复 | 中间态不暴露：静默重试，失败后回退 |

### 核心洞察
> **模型能力商品化，竞争优势转移到模型之外的工程实践**

## 七、工程范式演进

```
软件工程 → 提示工程 → 上下文工程 → Harness工程 → Loop工程 → Graph工程
```

**层层包含关系**：后者包含前者，每层扩展工程师的关注范围。

## 八、编排模式对比

### 工作流模式（Workflow）
- **特点**：预定义代码路径，确定性执行
- **优势**：严格流程控制、高安全性
- **局限**：缺乏变通性
- **适用**：关键流程、合规要求严格的场景

### 自主Agent模式（Autonomous Agent）
- **特点**：动态决策执行路径，根据环境反馈实时调整
- **核心能力**：自主规划、识别失败、调整策略
- **必须设计**：明确的停止条件
- **适用**：开放式问题、步骤数不可预测的任务

### 选择原则
```
优化提示词 → 考虑工作流 → 最后才引入自主Agent
```

## 九、护栏体系

### 三层防护
| 防护位置 | 护栏类型 | 功能 |
|----------|----------|------|
| **输入侧** | 相关性分类器 | 标记偏离主题的查询 |
| | 安全分类器 | 检测越狱、提示注入 |
| | 内容审核 | 标记有害内容 |
| | 基于规则保护 | 黑名单、长度限制、正则过滤 |
| **执行侧** | 工具风险评级 | 低/中/高风险分级，高风险需额外审查 |
| **输出侧** | PII过滤器 | 审查个人身份信息 |
| | 输出验证 | 确保回复与品牌价值一致 |

### 人工干预触发条件
1. **超过失败阈值**：重试次数或操作次数超限
2. **高风险操作**：敏感、不可逆、高风险操作

## 十、模型选型要点

### "御三家"闭源模型
| 厂商 | 特点 | 适用场景 |
|------|------|----------|
| **Anthropic（Claude）** | 复杂推理、编程、工具调用突出 | Agent开发首选 |
| **Google（Gemini）** | 超长上下文、强大多模态 | 长文本、图片视频场景 |
| **OpenAI（GPT/o）** | 能力均衡，用户最多 | 通用场景 |

### 国内模型
- **豆包**：国内延迟极低，适合实时交互
- **Kimi**：国内Agent能力较强
- **Qwen/DeepSeek**：开源模型，成本和可定制性优势

### 选型关键维度
1. **支持Reasoning**：绝大多数Agent需要
2. **输出token速度**：影响端到端延迟
3. **多模态能力**：按需评估

## 核心结论

1. **Agent = 大脑 + 眼睛 + 手脚**，三者缺一不可
2. **扩展眼睛和手脚是最主要的能力杠杆**
3. **上下文是决定性因素**：去掉任何组件都会导致系统退化
4. **Harness是竞争力所在**：确保Agent"可靠地做事"
5. **编排模式选择**：先优化提示词→再工作流→最后自主Agent
6. **安全是架构问题**：从第一行代码就要考虑
