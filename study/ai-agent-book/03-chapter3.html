《AI Agent 实战》第三章：用户记忆和知识库 - 核心知识笔记 ​

一、核心概念 ​

1.1 用户记忆系统 ​

  • 定义：针对单个用户的个性化记忆系统，构建关于用户的预测模型
  • 本质：主动、持续的学习过程，将分散对话中的关键信息显式提取和压缩
  • 目标：让 Agent 成为"懂你的助手"

1.2 知识库 ​

  • 定义：面向所有用户共享的集体知识存储
  • 用途：行业法规、公司流程、技术文档等
  • 目标：让 Agent 成为"领域专家"

1.3 记忆的三个层次 ​

层次名称核心能力示例
第一层基础回忆准确存储和检索无歧义的结构化信息"我的会员号是12345"
第二层多会话检索跨会话、跨对象检索相关信息并推理判断用户有两辆车时询问"为我的车预约保养"需找出全部车辆信息
第三层主动服务综合多会话信息提供预见性帮助预订航班时主动关联护照信息并发出过期预警

1.4 RAG（检索增强生成） ​

  • 核心思想：将 LLM 的生成能力与外部知识库的时效性相结合
  • 构成：检索器（找相关片段） + 生成器（基于片段生成答案）
  • 价值：利用训练时未见过的知识，无需重新训练模型

二、用户记忆的四种存储格式 ​

2.1 四种格式对比 ​

格式特点优势劣势适用场景
Simple Notes最小不可分事实O(1)操作，极低开销信息关联性丢失大量非关键对话事实
Enhanced Notes包含完整上下文的段落语义完整，适合细微理解存储冗余、更新复杂需要叙事完整性的场景
JSON Cards三层嵌套结构（类别→子类别→键值对）支持部分更新、可扩展强制分类丢失多维性结构化信息管理
Advanced JSON Cards加入叙事背景、主体身份、关系、时间戳解决消歧问题，精确区分实体生成维护成本高关键且少量的数据

2.2 核心设计张力 ​

简单性与表达力之间的权衡：

  • Simple Notes → 极致简单，牺牲语义完整性
  • Enhanced Notes → 叙事完整，牺牲结构化
  • JSON Cards → 结构化，牺牲灵活性
  • Advanced JSON Cards → 全面性，牺牲简单性

2.3 实践选择标准 ​

  • 关键且少量的数据 → Advanced JSON Cards（保证可检索性）
  • 大量且非关键的对话事实 → Simple Notes（降低成本）
  • 生产系统 → 混合模式

三、记忆系统的认知科学基础 ​

3.1 三种长期记忆类型 ​

类型定义人类例子Agent 对应
情景记忆关于具体事件和经历的记忆上周三和同事在意大利餐厅吃晚餐用户订了下周五去东京的航班
语义记忆从具体事件中抽象出的一般性知识意大利的首都是罗马用户是素食者、用户偏好靠窗座位
程序记忆关于行为模式和流程的记忆骑自行车的能力先搜索直飞→确认座位偏好→使用常旅客号

3.2 三套分类体系的关系 ​

分类体系回答的问题具体类别
记忆层次存在哪里？轨迹、用户长期记忆、业务状态
存储格式怎么存？Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards
认知类型存什么？情景记忆、语义记忆、程序记忆

三者关系：正交维度，可自由组合

四、RAG 完整技术栈 ​

4.1 文档分块（Chunking） ​

策略原理优势劣势
固定大小切分按固定 token 数切分，保留重叠实现简单、结果可预测无视文档结构
递归/结构感知切分按文档自然边界递归切分尊重文档结构需要文档有显式结构
语义切分在语义"断崖"处下刀切分质量高需要额外嵌入计算

实践起点：每块 256-1024 token，相邻块重叠 10%-20%

4.2 稠密嵌入（Dense Embedding） ​

核心原理：用深度学习将文本映射到向量空间，语义相近的内容向量距离近

技术演进：

  • Word2Vec：静态词向量，无法处理一词多义
  • BERT/BGE-M3：上下文感知，同一词在不同语境下有不同向量

相似度计算：余弦相似度（关注方向而非长度）

4.3 稀疏嵌入（Sparse Embedding） ​

核心原理：精确的关键词匹配，文档表示为极高维稀疏向量

BM25 算法要点：

  • 词频饱和：重复出现的边际贡献逐渐降低
  • 长度归一化：不同长度文档公平比较
  • IDF 加权：稀有词权重更高

优势：精确匹配技术代码、人名等 劣势：读不懂同义表达

4.4 混合检索三阶段 ​

┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  并行检索    │ ──→ │  结果融合    │ ──→ │  神经重排序  │
│ (稠密+稀疏)  │     │ (RRF/加权)   │     │ (跨编码器)   │
└─────────────┘     └─────────────┘     └─────────────┘

融合方法：

  • 加权归一化：保留得分信息
  • RRF（倒数排名融合）：只看排名，简单鲁棒

重排序价值：跨编码器对查询和文档深度交互匹配，精度远高于双编码器

4.5 检索质量指标 ​

指标直觉解释
recall@k（召回率@k）包含正确答案的文档出现在前 k 个结果中的查询比例
MRR（平均倒数排名）第一个相关文档排名的倒数平均值
nDCG（归一化折损累积增益）综合考虑所有相关文档的排名与相关程度

五、多模态信息提取 ​

5.1 三种技术范式对比 ​

范式原理优势劣势适用场景
原生多模态处理统一语义空间，ViT 切分图像块无与伦比的上下文保真度成本高版式复杂、信息密度高的文档
提取为文本OCR/转录后输入 LLM低成本、可缓存版式、图表信息丢失纯文本主导的文档
工具化分析文本摘要 + 按需深度分析工具兼顾低成本和高保真端到端场景不如原生模式交互式场景

六、知识组织方法 ​

6.1 RAPTOR（树状层次索引） ​

原理：自下而上递归抽象

  1. 切分文本块作为叶子节点
  2. 聚类语义相近的叶子节点
  3. 生成父节点摘要
  4. 递归形成知识树

适用查询：从概念逐步钻进细节的问题

6.2 GraphRAG（实体-关系图谱） ​

原理：将文档知识建模为知识图谱

  • 提取实体（人物、地点、概念）
  • 提取关系
  • 社区发现生成摘要

核心优势：

  • 多跳关系推理：天然支持沿关系边遍历
  • 实体消歧：同名不同实体通过关系边区分

局限：三元组提取导致语义降级，条件逻辑丢失

适用查询：关系性问题（"A 和 B 之间是什么关系"）

6.3 文件系统范式（OpenViking） ​

设计：将知识映射为虚拟文件系统

viking://
├── resources/          # 外部知识
├── user/memories/      # 用户记忆
└── agent/              # Agent自身

L0/L1/L2 三层按需加载：

  • L0（摘要）：~100 tokens，快速判断相关性
  • L1（概览）：~2,000 tokens，规划决策
  • L2（全文）：完整内容，按需加载

七、智能体化 RAG（Agentic RAG） ​

7.1 范式转变 ​

维度传统 RAG智能体化 RAG
模式被动管道主动探索
流程单向数据流迭代循环
检索自动化前置步骤Agent 调用的工具
能力找到文档片段解决复杂问题

7.2 ReAct 循环 ​

思考 → 行动（调用检索工具）→ 观察 → 评估 → [继续循环或生成答案]

7.3 核心价值 ​

  • 简单问题：传统 RAG 更高效
  • 复杂问题：智能体化 RAG 多轮迭代，显著提升准确率

7.4 安全边界 ​

  • 间接提示注入风险：检索文档可能包含恶意指令
  • 防御策略：
    • 指令与数据分离：标记来源，明确"供参考的外部资料"
    • 不让检索内容直接触发高风险操作

八、上下文感知检索 ​

8.1 问题根源 ​

标准分块将紧密关联的上下文分离，孤立文本块语义模糊

8.2 解决方案 ​

索引前用 LLM 生成包含核心上下文的"前缀摘要"，与前缀拼接后索引

示例：

  • 原文本："该公司第二季度的收入增长了 3%"
  • 加前缀："[节选自 ACME 公司 2025 年 Q2 财务报告'关键业绩指标'章节] 该公司第二季度的收入增长了 3%"

8.3 效果 ​

  • 增强 BM25：增加可精确匹配的关键词
  • 增强向量嵌入：注入关键语义背景
  • 检索失败率降低：结合 BM25 降低 49%，结合重排序降低 67%

8.4 与上下文感知压缩的区别 ​

维度上下文感知检索上下文感知压缩
时机索引期运行期
对象知识库文本块当前会话对话历史
操作补前缀、加背景按任务裁剪、去冗余

十、从结构化数据提取知识 ​

10.1 两阶段流程 ​

第一阶段：知识提取与结构化

  • LLM 将非结构化描述转为标准化 JSON
  • 核心挑战：定义全面且一致的数据模式

第二阶段：因子分析与重要性建模

  • 统计分析发现模式
  • 构建因子重要性层次模型

10.2 实践要点 ​

  • 采用"自下而上"因子发现策略
  • 模块化数据模式：核心模式 + 扩展模式
  • 构建"案件原型"用于相似匹配

十一、关键实践要点 ​

11.1 记忆系统设计 ​

  1. 评估先行：用三层次框架建立评估标准
  2. 分层设计：轨迹（当前会话）+ 长期记忆（跨会话）
  3. 压缩策略：重要性评分 → 聚类摘要 → 抽象泛化
  4. 隐私保护：日志脱敏，本地模型处理敏感信息

11.2 知识库构建 ​

  1. 索引选择：静态数据选 ANNOY，动态数据选 HNSW
  2. 失效内容检测：版本号、生效/失效时间元数据
  3. 权限过滤：检索层按调用者权限过滤
  4. 文件链接：知识条目间建立交叉引用，形成引用网络

11.3 检索优化 ​

  1. 混合检索：稠密 + 稀疏 + 重排序是生产级标配
  2. 上下文感知：索引阶段补前缀，成本可控（prompt caching）
  3. 结构化索引：简单方案不够用时再升级 RAPTOR/GraphRAG

十二、扩展思考 ​

12.1 核心问题 ​

  1. 冲突处理：当同一用户在不同会话提供矛盾信息时，记忆系统如何处理？
  2. 信息质量：上下文感知检索可能传播原始文档的错误，如何引入"信息质量"信号？
  3. 元认知问题：模型不知道自己不知道什么，如何正确触发搜索？
  4. 多模态翻译损失：图表转文本描述可能丢失空间关系，如何保留？

12.2 理论层面思考 ​

  1. "苦涩的教训"视角：本章构建的整个知识系统是否本身就是"手工设计"？未来是否会被"全量输入"替代？
  2. 领域知识库的未来：随着模型能力提升，领域知识库是否还有价值？
  3. 数据驱动 vs 专家规则：从数据中归纳规则能否达到人类专家手工编写规则的质量？

12.3 工程实践思考 ​

  1. 混合策略：成熟的 Agent 系统需混合使用多种记忆模式
  2. 分层互补：以自然语言保存核心信息，辅以结构化元数据索引
  3. 成本权衡：结构化索引需要大量 LLM 调用，应在简单方案不够用时才升级

十三、核心公式与算法 ​

13.1 BM25 评分公式 ​

$$\text{Score}(Q, D) = \sum_{i} \text{IDF}(q_i) \cdot \frac{\text{TF}(q_i, D),(k_1+1)}{\text{TF}(q_i, D) + k_1\left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}$$

  • $k_1$：控制词频饱和速度（常取 1.5）
  • $b$：控制长度归一化强度（常取 0.75）

13.2 余弦相似度 ​

$$\cos(\theta) = \frac{A \cdot B}{|A| \times |B|}$$

13.3 RRF（倒数排名融合） ​

$$\text{score}(d) = \sum_{r \in R} \frac{1}{k + \text{rank}(d, r)}$$

  • $k$：平滑常数（常取 60）
